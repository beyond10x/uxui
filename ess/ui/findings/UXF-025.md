The gate decision of a promotion names three requirements and a verdict for each. Since R-03 they
read as two fields side by side:

```
Requirement                                            Verdict
effort.actions, attention.glance_cost, completion.miss pass, fail, pass
```

Which requirement failed is the second word of one list matched to the second word of the other.
The verdicts are plain text: a verdict has a tone elsewhere in the studio (a badge), and a list has
none. What gets worse and what gets better read the same way once a promotion has more than one of
either: the fixtures have one each.

Before R-03 the same values were one line of JSON per list (UXF-005), which named each verdict
beside its requirement and was harder to read as a whole. This finding is the cost of that change.

The cause is the stock generator's: it has no drawing of a list of records but JSON, so the
document splits each list into one field per member (UXF-005, "R-03"). A known loss candidate.

Heuristic 10 (recognition over recall): partial.

Triage: frequency 1 of 11 scenarios (owner-trade-off, an anchor card), confidence 1 (the
screenshot alone; no reviewer ran), cost L. Priority 0.02.

Fix in one line: one row per requirement, its verdict as a badge beside it.
