Five filters of the studio document name their field bare (`name contains state.search`). The
filter reads the bare word as a literal, not as the row's field, so no row ever matches. ESS's own
examples write `row.name contains state.search`. `ess ui check` reports no error for the bare form.

What the person sees:

- Targets, Campaigns, Promotions and Judgements: typing in the search empties the list. "form"
  on Targets gives 0 rows although "Settings form" is listed, and the page says "Pick a base
  document to list its targets" (UXF-019).
- A variant: the "Axis switches" table is empty although the fixtures hold a switch from this
  variant. That table is the `signal` of the switch journey in `ess/ui/studio.uxui.yaml`, so a sent
  switch can never be seen.

The terminal renderer shows the same empty list: the cause is the document, not the React target.

Heuristics 14 (unmistakable end state) and 6 (errors cheap): fail.

Triage: frequency 2 of 11 scenarios (filter-targets, switch-axis), confidence 2 (the trial, the
terminal renderer and the heuristic review agree), cost S. Priority 3.27.

Fix in one line: write the five filters with `row.<field>`.
