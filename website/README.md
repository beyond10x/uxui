# uxui documentation site

The public site at <https://beyond10x.github.io/uxui/>. It is Docusaurus on the shared beyond10x
Docs System (`@beyond10x/docs-system`, pinned by commit in `package.json`), served under `/uxui/`.
The site build is the only Node in this repository; everything derivable is generated by the POSIX
sh script `tools/docs.sh`.

## What is generated and what is written by hand

| Path | Source |
|---|---|

| `docs/reference/metrics.md` | Generated from `docs/metrics.md` |
| `docs/reference/glossary.md` | Generated from the glossary of `docs/brief.md` |
| `docs/reference/specification.md` | Generated from `ess/system.yaml`, `ess/domains/*.yaml` and `ess/ui/studio.ui.yaml` |
| `docs/roadmap.md` | Generated from `docs/roadmap.md` |
| `docs/status.md` | Generated from `data/status.json` |
| `data/status.json` | Written by hand from `docs/roadmap.md`; the landing page and `docs/status.md` read it |
| `docs/index.md`, `docs/getting-started.md`, `docs/limitations.md`, `docs/concepts/`, `docs/guides/` | Written by hand; concept and guide pages name their sources in `source` |
| `product.json` | The landing page (`b10x-product-landing/1`), written by hand |
| `src/css/landing.css` | The landing page's four custom properties over the docs-system theme: `--uxui-density` (0.85, written by `ux-search landing promote` from the frontier of `docs/campaign-2026-11-26-docs-landing-engine.md`, evidence `docs/promotions/2026-11-26-docs-landing.evidence.json`) and `--uxui-heading-scale` (from `docs/campaign-2026-11-24-docs-landing.md`), `--uxui-hero-align` and `--uxui-hero-lede-inline` (the hero's alignment). They are the style axes of the campaign in `docs/campaign-2026-11-26-docs-landing-engine.md`; a variant of it also sets the docs-system colour tokens `--b10x-color-*` in two rules it appends |
| `src/css/site.css` | The layout rules over the Docusaurus theme that the page checks hold (Layout, below); no campaign writes it |
| `docusaurus.config.ts`, `sidebars.ts` | Site configuration and the explicit sidebar |

Never edit a generated file by hand. From the repository root:

```console
sh tools/docs.sh generate
sh tools/docs.sh check
```

`generate` rewrites the generated files. `check` writes nothing under `website/` and fails on a
generated file that is missing, stale or edited, and on any page that breaks the rules below.
`task check` runs it; `task docs-generate` and `task docs-check` are the same two commands.
`tools/docs.test.sh` proves the check fails on broken copies of the tree.

## Page rules

Every page under `docs/` is plain Markdown (`.md`, never `.mdx`) with front matter:

- `title`, `sidebar_position` and `description` on every page; concept and guide pages also carry
  `lede` (the sentence the page opens on) and `source` (the files it is written from).
- A front matter value that YAML would not read as one string (it contains `: ` or ` #`, or ends
  with `:`) must be quoted.
- Outside code: no `{`, no `import` or `export` line and no capitalised tag. The generator escapes
  `{` and `<` in the text it copies.
- Callouts are admonitions with the title in brackets, `:::caution[Planned]`.
- No page names a home path or internal planning material. No company, customer or person names.
- Links between pages name the `.md` source. Docusaurus refuses a broken link, anchor or Markdown
  link at build time.

## Layout

The site keeps three things in view on every page, at 1440x900 and 390x844, in light and dark: the
navbar, the theme toggle and, from 997 px wide, the docs sidebar; the keyboard reaches the navbar
and the theme toggle. The page checks that say so are
`engine/browser/tests/fixtures/checks/uxui-docs.checks.yaml`. Two rules of `src/css/site.css` hold
them over the Docusaurus theme:

- The theme toggle stays in the navbar at phone width. The theme hides it below 997 px and keeps a
  copy only in the collapsed menu, where neither the eye nor the keyboard finds it without opening
  the menu. The navbar at 390 px holds the brand, the menu button and the toggle without overflow.
- The docs sidebar is fixed to the viewport's height. Sticky, as the theme has it, the footer
  pushed it up at the bottom of a page, so its top left the viewport (by 222 px on the metrics
  page). The footer of a docs page starts beside the sidebar; the sidebar's list still scrolls on
  its own.

Measured on a local build with `ux-browser checks --build website/build` (15 pages, 566 checks):
103 failed before these rules (4 always-visible misses and 1 keyboard miss on the landing page, 6
and 1 on each of the 14 docs pages), 0 after, with no overflow and no page scroll. No gate or CI
step runs these checks: the site's workflow builds the site without a browser, and the gate starts
none. They are run by hand after a change of the site's layout:

```console
cd website && npm ci && npm run build && cd ..
cargo build -p ux-browser --locked
target/debug/ux-browser checks --config engine/browser/tests/fixtures/checks/uxui-docs.checks.yaml \
  --build website/build --project uxui-docs --assessment page-checks --out uxui-docs.evidence.json
```

## Build and preview

Node 22. The Docs System is a Git dependency, which npm installs only with `--allow-git=root`
(set in `.npmrc`).

```console
cd website
npm ci
npm run build
npm run serve
```

`npm run build` writes `website/build`; `npm run start` serves a live-reloading preview. A changed
dependency is installed with `npm install` and lands as a reviewed `package-lock.json` change.

## Provenance and delivery

```console
sh tools/docs.sh provenance website/build "$(git rev-parse HEAD)"
```

`provenance` binds a built site to the commit it was built from. It writes
`.well-known/b10x-site.json` (schema `b10x-project-site/v1`, with the repository, the commit and
the `/uxui/` base), the route inventory `.well-known/b10x-routes.json`
(`b10x-project-routes/v1`), and `.nojekyll`.

Building and deploying are separate, and this repository holds no deployment credential:

- `.github/workflows/pages.yml` runs on every push and pull request with `contents: read` only and
  persists no checkout credential. It runs the docs check and its test, builds the site, runs
  `provenance`, and on a push to `main` uploads the result as the artifact `b10x-project-site`. It
  deploys nothing.
- `.github/workflows/b10x-docs-site.yml` runs after a green `pages.yml` push to `main`, only for the
  bot. It calls the shared `project-site.yml` publisher in the Website repository, pinned by commit,
  which downloads that exact artifact, verifies its manifest against the commit and base, and
  deploys it to Pages. It never runs this repository's code.

## Security boundary

- The browser gets the static output of the Docusaurus build: no third-party fonts, scripts or
  analytics are added by this site.
- The pages are passive Markdown (see the page rules), so a page cannot run code at build time.
- npm resolves dependencies from `package-lock.json` and installs the one Git dependency, the Docs
  System, at the commit `package.json` pins.
- CI builds with `contents: read` and no credential; deployment is the shared publisher's.
